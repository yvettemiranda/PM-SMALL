## 观察项

- Polymarket 正式结算 API 的字段和可用性仍需在长期运行中持续核对，不能把不确定结果当作结算。
- 钱包、签名、真实订单和链上写操作属于后续阶段，本任务不得引入。
- v0.5.0 正式长期 PAPER 运行、剩余故障矩阵和性能/容量验证仍是未完成项；不能把当前自动测试或单一账本故障演练通过当作长期验证完成。
- 全市场分页扫描可能显著增加订单簿请求量和 WebSocket 订阅 Token 数，需在 v0.5.0 长时间验证中观测官方速率限制与订阅容量；这不是本轮用固定上限掩盖的筛选规则。
- 约2,000至2,400 Token完整规模的短时盘口就绪、有界关停和三轮连续断线恢复已通过，但长时间保持、长期窗口内断线和重复扫描稳定性仍需验证。
- 10分钟和15分钟PAPER运行均未观察到可确认的低价Token市场成交；受控运行时测试已覆盖纸面买入、自动卖单、首次卖出撤买和健康账本，但真实公开行情触发仍需在长期运行中观察。
- 周期验证只负责发现问题、暂停和阻止重新运行，不会自动修复不一致账本；未来服务器运维仍须先备份现场、定位差额并人工核对修复，禁止关闭验证或强改状态绕过门槛。
- 进程资源指标已可留证，但当前Mac短时结果不能替代未来Linux服务器基线；正式长期窗口前不设置缺乏证据的内存自动失败阈值。
- 有界重试能避免单个暂时错误立即丢弃扫描进度，但不能证明真实Gamma/CLOB接口长期无压力；需用新增请求、重试、限流和临时错误计数确定长期频率，持续故障在3次请求后仍会保守失败。

## 已处理

- 本地v0.4.0及后续v0.5.0阶段提交原先未同步到GitHub；本轮功能与审查基线`6fbd1d9`已快进推送并核对，后续同步记录也遵循提交后立即推送和复核流程。
- 旧公开WebSocket适配依赖`initial_dump`默认值，大订阅只收到增量事件；现改为显式请求，836 Token在约2.72秒达到836/836完整盘口。
- 此前2,452 Token订阅后的实例关停超过20秒，另一次扫描中实例观察约5秒仍未退出；现增加扫描取消、WebSocket局部超时和5秒进程总截止线，扫描中`SIGINT`冒烟已以0退出。
- 新链路完整30天扫描生成2,405个候选，2,405/2,405初始盘口全部就绪并稳定超过60秒；大连接`SIGINT`约319毫秒以0退出。
- 2,400 Token断线注入中，一次1006重连失败后服务自动再次重试，约10.9秒恢复2,400/2,400且错误清空；未就绪期间没有放宽成交门槛。
- 2,099 Token连续3次断线均先清除就绪状态，再完整恢复2,099/2,099；最终累计指标4/4/3/3、错误为空，并增加三轮固定回归测试。
- 10分钟PAPER留证20个样本正常完成，传输/关键/周期验证失败均为0；100张买单资金占用、SQLite完整性和同库重启恢复均通过。
- 15分钟受控重启留证发现进程级计数归零会使首末值漏掉重启前100张自动买单；汇总现用统一窗口聚合行情、成交、自动买入/撤买、结算和验证计数的首末值与最大值，CLI测试直接覆盖`100→0`，原始逐样本记录继续保留。
- 隔离SQLite副本中的保留资金不一致已触发周期自动暂停、即时校验503和启动409；修复后即时校验、重新启动、同库冷启动、100/100盘口恢复及15样本监测均通过，操作边界已写入`docs/PAPER_SOAK.md`。
- 提交前审查发现留证工具可能把零有效样本记为成功，或在一个安全接口已返回关键异常、另一个接口超时时丢失前者；现已分别保留返回结果并补充CLI集成测试，累计周期失败也会停止。
- 留证工具原先每次读取完整候选数组，真实全市场规模下会增加无关负载；现使用`/api/status?compact=true`只读取候选数量和诊断。
- 双轴审查发现异常持仓行可能被汇总余额掩盖；周期验证现逐行拒绝非正数量/成本，并将所有非零异常行计入开放持仓。
- 双轴审查发现暂停写入失败、自动服务继续改账及旧成功结果残留风险；现增加进程内安全闩，暂停无法持久化时仍冻结除卖单减仓外的自动账本变更，验证异常时清空旧结果并保留错误。
- 双轴审查发现冻结期间首次卖出后，遗留买单可能在恢复时重新成交；恢复 `RUNNING` 现会先撤销这类买单，并继续由 `first_sell_at` 阻止同Token新买。
- 结算身份不匹配的错误信息原先只包含 market，导致服务测试无法定位 condition；已改为同时包含 market 和 condition。
- 官方 `50/50` 结果原先会被当作未最终结果等待；已增加按比例纸面回收，并拒绝其他非 `1/0`、非 `0.5/0.5` 向量。
- 变更审查发现前端结算/持仓字段直接进入 `innerHTML`；已增加 HTML 转义并覆盖候选订单的动态字段。
- 变更审查发现结算目标关联缺少 `condition_id` 约束、数据库入口缺少正式结果门槛；已修复并补充测试。
- `CandidateService.refresh()`原先在清理活动扫描标记前生成返回快照，导致已等待完成的手动刷新仍显示`scanning=true`；现改为清理后再生成快照，并固定覆盖暂时失败保留候选及后续恢复。
