# Bugs And Risks

## 活跃风险

- 新活动前五个片段的业务 RSS 峰值从 844.6MiB 逐段升至 968.9MiB，扫描耗时峰值从 106.64 秒升至 187.36 秒；只读复核时业务容器约 936.9MiB，服务器可用内存约 467MiB、磁盘占用 17%。尚未触发硬失败或限流，但资源与扫描时长上升趋势应作为长期容量验收风险持续观察。
- 正式 TEST 新活动当前已按用户授权停止，服务器为 `TEST + LIVE_DISABLED + PAUSED`；发布并恢复后仍由服务器独立运行，Codex 关闭不影响采样。用户明确不设置自动提醒，因此每个新完成片段仍须等用户回到当前任务后决定计入或排除。
- Schema 15 的 Event 互斥、完整兄弟盘口门槛、共享 FAK Preview、确定性仲裁、原子锁/账本、冻结预算和 legacy conflict 迁移均已实现并通过回归；后续修改仍必须维持这些失败关闭不变量。
- 当前正式 TEST 基线为 Schema 15、100U 空账本。用户已明确放弃正式验证前的旧账本数据并授权删除旧备份；这些历史数据不可恢复，后续不得再描述为仍有服务器备份。此前 100U→1000U 与 RUNNING 均已确认是用户手动操作，不再作为异常风险。
- 静态预筛、有界盘口并发、增量/分片 WebSocket 和断线保留展示已通过本地多轮实扫与服务器短时冒烟；这只证明候选跨一轮重扫保持、单连接和短时资源正常，仍不能替代正式长期 TEST 的限流、断线和容量验收。
- Dashboard 的“重连候选”保留最后一次有效价格但明确 `tradable=false`；任何后续修改都不能把陈旧报价重新用于自动或手动买入。
- “持仓实时价值”必须复用后端按当前可卖盘口和费用计算的持仓市值，不能在页面另造与账本口径不一致的估值；无可卖 Bid 时仍按现行规则计为 0。
- 持仓折叠只允许发生在页面渲染层；Dashboard 接口仍须返回全部当前持仓，不能以 20 条上限截断交易或监控数据。
- Polymarket 首页栏目依赖公开接口；首次请求失败时使用当前 14 栏目的内置回退，后续扫描继续尝试同步。正式长期验证需观察栏目变更、接口失败和缓存刷新，不得把一次同步成功当作长期可靠性结论。
- v0.5.0 正式长期 TEST 运行、真实接口限流、全量扫描周期、长期 WebSocket 容量/断线、服务器资源和公开行情成交样本尚未验收；不能把自动测试或短时冒烟当作完成。
- 全部开放事件分页不再使用事件日期窗口，正确性更高但扫描规模可能增加；必须在用户制定的长期验证中测量真实耗时、请求量和限流频率，不能用隐藏数量上限规避。
- 服务器短时冒烟首次全量扫描已遍历 181 页、18,002 个事件并成功完成，但一次成功不能代表长期 API 限流、反复扫描周期或 WebSocket 容量已经验收。
- 旧 v0.4 目标卖单缺少真实最小下单量与动态费率。迁移 011 用最小正值保证 TEST 旧持仓可以退出，但旧仓位的费用近似不应当作未来 LIVE 成绩；需要精确基线时应在暂停后使用受控 TEST 重置重新开始。
- Polymarket 正式结算字段和可用性仍需长期观察；任何不确定结果都必须继续等待。
- 当前 Nginx Basic Authentication 只适合单用户 TEST。未来 LIVE 必须重新设计身份、会话、CSRF、审计和凭据边界。
- 正式 TEST 的累计时长由用户逐段确认：每 4 小时及每次配置变化形成独立节点；安全、SQLite、账本或 Event Lock 硬失败段不得通过人工决定计入。达到累计 72 小时后仍须完成最终审计，不能把时长达标直接等同于验收通过。
- 正式 TEST 监控按 60 秒采样；有效采样率和墙钟覆盖率任一低于 99.5% 都自动拒绝该段。监控容器异常重启只会强制 PAUSED，不会自动续跑；恢复或跨任务累计必须保留旧证据并由用户重新决定，不能静默拼接。
- 新活动自身报告从 0/72 小时开始，跨活动总进度必须另加旧活动已确认的 8 小时；当新活动确认计入达到 64 小时时必须受控停止，不能误等到新活动自身 72 小时。
- 公网 SSH 当前在服务端 banner 前关闭连接；本轮通过已登录腾讯云控制台完成可审计部署。正式长期 TEST 前应单独核对 SSH 服务、云防火墙和登录策略，不能通过放宽公网访问绕过现有安全边界。
- 钱包、签名、真实订单和链上写操作属于后续阶段，本任务不得引入。

## 已处理

- 正式交易审计发现同 Token 的目标卖单碎片会漏卖：113 个活动 target 中 25 个低于市场最小量，Canada GDP June 的 8 个 target 各自小于 5 份但合计 37.337455 份且目标价以上深度充分。用户已授权暂停与最小修复；实现现把有序 target 聚合到合法最小量，以批次最高目标价失败关闭，并由 Preview 与真实 SELL 共用规划器。聚合 Fill 的微单位舍入反算差异也已修复；两轮红绿回归、全量 32 文件/298 项、typecheck、build、语法/差异检查和双轴复核均通过，待 GitHub/服务器发布。
- 继续正式 TEST 前，旧监控镜像已不在 Docker 本地缓存，且首次无 `sudo` 的 `prepare` 因 Docker socket 权限在构建前安全退出；重新以服务器既有权限模型准备当前 SHA 镜像后通过，应用和数据库在准备阶段始终 PAUSED。
- Event 816196 跨轮验证误报：`validatePaperState()` 现只比较当前 ACTIVE Event Lock 的 active Token；合法兄弟 Token 新轮通过，真实同轮首次卖出后再买仍失败。修复已通过红绿回归、全量测试、服务器旧库即时验证与同库重启。
- 正式监控重启循环：supervisor 等待阶段现持有可在信号时清理的定时句柄，不再以 unsettled top-level await/退出码 13 结束。新服务器镜像独立冒烟保持 `running=true / restarts=0`，旧循环容器已停止。
- 新监控镜像服务器冒烟第一次在启动容器前因 UID:GID 命令多带引号而安全退出；未触碰正式活动或数据库。改为分别读取数字 UID/GID 后通过，临时容器与目录均已清理。
- 正式 TEST 首次启动的证据目录权限问题：包装脚本在 `sudo` 下创建 `root:root / 0700` 目录，而监控镜像以非 root 用户运行，导致 `campaign.json` 前以 `EACCES` 安全失败。现从实际监控镜像读取数字 UID:GID，并在启动容器前递归交接证据目录所有权；回归、293 项全量测试、typecheck、build、Bash/前端语法和差异检查通过，提交 `df01ecf626734e54123383357b11af22f1fe2cda` 已部署。第二次启动成功，监控重启为 0，失败现场与基线保留以供审计。

- Dashboard 曾把所有 Event 仅按生命周期进度混排，低进度待定项会占据默认前 20 项并遮住真实可交易项；现固定 `READY` 置顶，再在可交易组和待定组内部按 ASC/DESC 排进度。公开接口回归、293 项全量测试及服务器 9 `READY` + 188 待定实扫顺序均通过；未改变扫描、资格或交易逻辑。
- FAK Preview 曾对每个 BUY Fill 独立读取整本 Bid depth 并累加，导致多个 target 重复计算流动性；现按真实 SELL target 顺序复用 `planFakSell()`，每次规划后扣减 mutable Bids，聚焦回归证明 Preview Coverage 与实际 `executeTestFakSells()` 一致。真实 SELL 路径和其他仲裁层级未改；运行提交 `4f4f12e9eb91ef2e002906e7765a0fb6d8318a6c` 已完成 GitHub/Linux 同步及 PAUSED 部署验证。
- 任意标准多元 Schema 15 已发布：运行时代码 `cb1472c90039ed72e9038821434cf22b45153f43` 完成 GitHub/Linux 同步；迁移备份、原子升级、同库重启、账本/SQLite、容器、端口、HTTPS/认证和 PAUSED 安全状态均通过。

- 增量订阅后新增 Token 的断线 stale-ready 窗口：断线按当前订阅全集清除就绪，重连后每个 Token 必须收到新完整 Book 才恢复；聚焦回归通过。
- 公开价格、费率与开放状态边界：价格严格在 0–1U、数值必须是安全整数；已知 event type 即使 schema 不完整也会立即终止行情队列、丢弃排队事件并断线清除旧 ready，未知扩展帧继续忽略；REST 任一非法价格使整本 Book 未就绪且同时核对 Condition ID；费用启用状态明确、费率 0–1、指数 0–10，事件/市场 closed 与 archived 必须明确 false。
- 首页栏目 pending/失效窗口：非全选时只有本轮同步白名单内 ID 可进入盘口请求；同步未就绪或为空时该轮失败关闭，全选扫描不被挂起阻塞。
- 结算与账本证据：数据库只接受 Token 身份无首尾空白的 1/0 或 50/50；已结算 Condition 收到任何不同或非法重放都会先持久化 `PAUSED` 和冲突审计，再从结算审计核对 payout Token 身份；周期验证交叉核对 fill 合法性、订单成交量/费用、仓位反算、目标覆盖与资金守恒。
- soak 对 HTTP 200 但无法解析的状态或即时账本响应立即记录关键失败并退出，不再把 malformed 成功响应当作空结果。
- 失效 GitHub CLI 登录阻塞发布：已通过官方设备流程重新授权，两个功能提交成功推送，远端与本地 ahead/behind 为 `0/0`。
- 服务器冗余清理：在复验最新 Schema 15 回滚备份后，按用户明确授权删除 6 个旧部署备份和旧迁移备份目录，并清理 1.352GB 未使用 Docker 构建缓存；当前数据库、运行镜像、活动日志和最新备份保留，清理后运行与公网验证通过。
