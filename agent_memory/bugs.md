# Bugs And Risks

## 活跃风险

- v0.5.0 正式长期 TEST 运行、真实接口限流、全量扫描周期、长期 WebSocket 容量/断线、服务器资源和公开行情成交样本尚未验收；不能把自动测试或短时冒烟当作完成。
- 全部开放事件分页不再使用事件日期窗口，正确性更高但扫描规模可能增加；必须在用户制定的长期验证中测量真实耗时、请求量和限流频率，不能用隐藏数量上限规避。
- 服务器短时冒烟首次全量扫描已遍历 181 页、18,002 个事件并成功完成，但一次成功不能代表长期 API 限流、反复扫描周期或 WebSocket 容量已经验收。
- 旧 v0.4 目标卖单缺少真实最小下单量与动态费率。迁移 011 用最小正值保证 TEST 旧持仓可以退出，但旧仓位的费用近似不应当作未来 LIVE 成绩；需要精确基线时应在暂停后使用受控 TEST 重置重新开始。
- Polymarket 正式结算字段和可用性仍需长期观察；任何不确定结果都必须继续等待。
- 当前 Nginx Basic Authentication 只适合单用户 TEST。未来 LIVE 必须重新设计身份、会话、CSRF、审计和凭据边界。
- 钱包、签名、真实订单和链上写操作属于后续阶段，本任务不得引入。

## 已处理

- 具体市场与事件时间不一致可能造成错误筛选：现按市场自身时间计算，缺失才回退事件时间，并取消事件日期窗口截断。
- 买入后同一盘口已经满足目标却不卖：买入创建目标后立即复查并执行目标卖出。
- 旧卖单迁移后 `min_order_size=0` 导致无法退出：新增迁移 011 仅为活动旧目标回填兼容最小正值。
- 已确认不需要逐 Token 勾选和手动新一轮：运行时选择方法及公开新一轮 API 已移除，完整卖出后自动循环。
- 公开模式与长期验证工具混用 PAPER/TEST：状态判断、验证端点和公网验收脚本已统一为 TEST；内部数据库命名继续兼容。
- LIVE 复用边界被 TEST 模式硬编码：核心编排现只要求执行适配器已启用，并以通用订单引用返回；当前禁用适配器仍失败关闭。
- 相同或重放盘口可能生成新版本并重复成交：现以单侧完整盘口状态生成稳定版本，重复增量不换版，SQLite 跨重启保留消费。
- 资金不足的候选被尝试缓存永久跳过：缓存键现包含现金和策略更新时间，其他持仓释放资金后会重新执行资格与数据库保护。
- 体育开赛、tick、升级暂停、迁移原子性和无标签伪类别存在分叉或失败开放：现已进入统一资格/Schema 12 防护并有固定回归。
- 多档 FAK 买单现金完整使用时，首档价格估算份额可能造成 `FILLED` 订单的原始份额大于实际成交份额：运行时已按实际总成交份额闭合，Schema 13 已无损归一服务器两条旧记录；账本验证和重启检查均恢复通过。
