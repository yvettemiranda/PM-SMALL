## 当前业务规则

- 当前架构升级目标是统一建模为 `Event -> 多个 Market -> 每个 Market 的 YES/NO Token`：Token 继续是盘口、成交、仓位和 Condition 结算单位，Event 升为候选仲裁、每轮预算和互斥锁单位。标准多元 Event 支持任意安全整数 `resultCount >= 2`；增强型负风险市场继续排除。
- 市场类型配置分为二元（2）、三元（3）和多元（>=4）三类；升级保留既有二元/三元选择，多元默认关闭。未锁定 Event 只有在全部静态合格兄弟 Token 都取得新鲜完整盘口后才允许仲裁，实际首笔成交后才原子创建 Event 锁。
- 同一 Event 每轮只允许一个 Token 实际成交；首笔卖出后整个 Event 进入退出态，不得再买入。全部卖清或 Condition 结算清仓后在同一事务释放 Event 锁，之后仍开放的兄弟市场可参与新一轮仲裁。
- 遍历全部开放事件分页，不用事件日期窗口或本地数量上限截断。资格按具体市场判断：开放、可下单、有订单簿、有 Condition ID，类别和二元/三元符合配置。类别只显示 Polymarket 首页栏目并保存官方 Tag ID；无标签市场仅在“全选”下参与，不制造伪类别。
- 具体市场总时长的最短、最长值均可在 1–365 天内自由设置，默认 1–30 天；优先用市场自身时间，缺失才回退事件时间。剩余时间不参与筛选。
- 生命周期进度是硬筛选条件，范围 1% 至 100%，默认 `<=20%`；超过门槛不得显示或新买，已有持仓继续卖出和结算。
- 不设历史成交量硬过滤；最低买价固定 1¢，还必须有有效 Best Bid、Bid/Ask 比例达到用户门槛（默认 50%）、完整盘口、可执行深度和满足最小下单量。
- TEST 按 Best Ask 执行 FAK 买入，未成交余量取消；目标卖价为 `max(买价+1¢, 买价×1.5)`并按 tick 向上取整，Best Bid 达标即 FAK 卖出。
- TEST 已消费盘口深度按单侧完整盘口状态的稳定版本持久化；相同快照、重复增量和重启后的等价快照都不能重复成交。
- 买入后立即用同一盘口复查卖出；首次卖出后本轮停止新买，完整卖出且未正式结算时自动开始下一轮，无手动新一轮入口。
- 动态费用计入买卖与盈亏；无 Bid 时持仓可实现估值为 0。正式关闭并确认结果后自动 TEST 结算和模拟赎回。
- UI 为手机优先单列：配置、资金摘要、当前持仓、扫描市场；资金摘要为总资金/持仓实时价值/持仓数，当前持仓默认前 20 项。扫描 Event 固定将可交易项排在待定项之前，两组内部由单按钮切换生命周期进度正序/倒序。无最近活动、程序诊断和逐 Token 勾选。LIVE 锁定。

## 验证与失败原则

- 数据缺失、盘口不完整或结果不确定时保守等待，不推定成交或结算。
- 开放/费用状态、价格边界、盘口身份或首页栏目白名单不明确时同样失败关闭；断线后的每个 Token 必须等新的完整盘口才能恢复交易就绪。
- 账本验证失败时暂停并冻结增仓，保留现场；目标卖出减仓仍可执行。
- 周期验证必须用 fills 反向核对订单成交量、费用和当前仓位；soak 的安全端点即使返回 HTTP 200，只要结构无法解析也必须立即失败。
- 每轮运行时代码、迁移、测试、公开接口或关键 UI 改动都必须执行匹配的测试、类型检查和构建，并明确未验证项。
