# Context

## 项目

- PM-SMALL：基于公开 Polymarket 数据的 PAPER 交易闭环项目。
- GitHub `origin/main` 是唯一交付进度基线；本地增量只有在验证、审查、提交、推送并核对远端后才算完成同步。

## 边界

- 当前阶段已完成 v0.4.0 纸面结算闭环；v0.5.0最终TEST UI已完成，下一步是Linux PAPER部署，之后才进入正式长期PAPER验证。
- 纸面闭环和长期验证完成前，不接入钱包、不提交真实订单、不执行链上写操作。
- 保持现有实盘执行器禁用状态，数据缺失或状态不确定时保守处理。
- 到达正式长时间PAPER验证阶段后停止，由用户制定运行时长、故障场景和验收计划；计划确认前不自行启动，短时预检不得计入正式验收。
- 最终运行目标包含Linux服务器部署；已验证并审查的提交必须同步到用户GitHub仓库，不只保留在本机，每轮结束前都要核对远端SHA。
- 已确认执行顺序为“最终UI → Linux PAPER部署与短时冒烟 → 用户制定计划 → 正式长期验证”；UI与部署冒烟不计入正式长期验收。

## 验证目标

- 事件结算、纸面赎回、资金回收具备幂等、资金守恒、审计记录和重启恢复能力。
- 正式结果只接受 `closed=true` 且 UMA 状态为 `resolved`/`settled`；支持 `1/0` 与 `0.5/0.5` 纸面回收。
- 周期只读验证覆盖 SQLite、资金守恒、订单成交范围、挂单占用、持仓卖单覆盖和结算残留；失败时保留现场，除卖单减仓外冻结自动账本变更，修复通过前不得恢复 `RUNNING`。
- 候选扫描暂时失败时保留最近成功候选并暴露失败状态，后续成功扫描再替换候选并清除错误；等待手动刷新完成时必须返回`scanning=false`。
- 事件分页和订单簿批次对限流、传输、异常响应及`408/425/5xx`执行最多3次原位只读请求（退避1秒、2秒）；永久性`4xx`不重试，取消可中断请求或退避。诊断与长期证据保留请求、重试、限流和临时错误计数。
- 长时间运行、完整故障注入、全市场接口速率和 WebSocket 容量仍需真实验收；自动测试不能替代这些结果。
- 长期JSONL样本记录进程运行时长、RSS、堆总量/已用量和外部内存，汇总保留窗口最大值；正式Linux基线产生前不据此设置自动失败阈值。
- 30天默认窗口的首次真实完整扫描耗时308.239秒，遍历12,631个事件、10,972个合格Token订单簿并生成2,452个候选；该单次结果不能替代持续容量验收。
- 公开Market订阅必须显式发送`initial_dump: true`；当前服务省略该字段时大订阅只收到增量事件。新适配层836 Token只读复验在约2.72秒达到836/836完整盘口。
- 扫描取消、WebSocket局部关闭超时和5秒进程关停总截止线已建立；扫描中的服务器`SIGINT`冒烟以退出码0结束。
- 新链路完整30天复验耗时252.208秒，遍历12,639个事件、读取10,770个订单簿并生成2,405个候选；初始盘口达到2,405/2,405并稳定超过60秒，大连接`SIGINT`约319毫秒以0退出。
- 2,400 Token真实断线注入后，第一次重连遇到1006异常并保持未就绪，自动再次重试后约10.9秒恢复2,400/2,400，最终错误为空。
- 2,099 Token短时重复断线探针连续3轮均先清除完整盘口，再在5.868、5.472和5.627秒恢复2,099/2,099；最终累计连接/完整盘口/异常断线/恢复为4/4/3/3且错误为空，长期稳定性仍待验收。
- 独立数据库10分钟PAPER运行得到20个有效样本、0传输错误、0关键错误；扫描后2,386/2,386盘口、100张买单和10次无失败周期验证保持一致，SQLite离线核对及同库100单重启恢复通过。
- 新版累计诊断15分钟PAPER运行得到28个有效样本、0关键错误；受控同库重启产生2次连续传输失败后恢复100张活动买单，第二轮扫描达到2,082/2,082盘口。SQLite完整性和99,990,000微单位挂单占用均通过，真实成交仍为0。

## UI约定

- `MAX_MARKET_DURATION_DAYS` 表示市场从开放到结束的总时长上限，不是剩余时长。
- 最终 UI 使用离散滑杆节点 `1、7、14、30、60、90、120、180、360、365` 天，默认 30 天；设置已持久化并直接接入全市场扫描安全窗口和精确筛选。
- UI必须手机优先并支持至少320px宽度；左上角显示`TEST / LIVE`，其中`TEST`仅替换界面文案，内部仍为`PAPER`，`LIVE`继续锁定。
- 默认主界面只保留总资金/总盈亏/已实现/未实现、当前持仓和扫描市场；桌面和手机均使用单列竖向布局。配置按需展开，包含二元/三元多选、`1¢`至`3¢`整数最高买入价（默认`≤3¢`）和总时长滑杆。
- 持仓和扫描项都显示市场链接、结果方向、价格和市场全生命周期进度，持仓买入结果使用醒目标签；扫描结果支持进度正序/倒序，默认全选进入TEST自动交易范围，支持全选/清空，首屏20项并每次再显示20项。
- 最近活动、筛选说明、程序/服务器状态及详细诊断不显示在默认主界面；手机使用纵向列表而不是宽表格。
- 最终视觉采用已确认的组合：Vercel轻量骨架、Coinbase财务数字表达、Binance市场行密度和PM-SMALL青绿色。生产界面已完成桌面、390px和320px真实浏览器验收；320px不得产生横向溢出。
- 扫描市场选择按Token结果方向持久化，默认全选；排除或清空会撤销对应未成交PAPER买单并阻止继续自动买入，但已有持仓和减仓卖单不受影响。
- 筛选保存后必须立即过滤尚未替换的旧候选，并在自动及手动PAPER新买入口同步复核；资金盈亏必须统计全部正数量当前持仓，不得受默认20项展示或数据库查询上限影响。
- Linux部署必须另行落实反向代理认证或受限网络访问；本轮UI不引入账户、钱包、签名或LIVE凭据。
