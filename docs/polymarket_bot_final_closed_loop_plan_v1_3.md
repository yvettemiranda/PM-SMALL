# Polymarket 低价合约自动挂单交易机器人最终闭环方案 V1.3

## 一、项目目标

开发一套可在测试模式和实盘模式之间切换的自动交易程序。

程序自动筛选符合条件的 Polymarket 市场，对价格处于连续 1—3 美分区间的 YES 或 NO Token，按照用户设定的固定金额提交 Maker 买单。买入成交后，自动按固定规则挂出 Maker 卖单；卖单未成交则继续持有至市场正式结算。所持方向获胜后自动赎回，结算资产返回可用余额并关闭交易。

核心流程：

`市场筛选 → 固定金额挂 Maker 买单 → 成交后自动挂固定卖单 → 首次卖出后停止继续买入 → 未卖出持有至结算 → 获胜自动赎回 → 资金回到账户`

---

## 二、运行模式

### 1. 测试模式

测试模式使用真实市场数据，但不提交真实订单。

功能包括：

- 使用真实市场、价格和订单簿数据；
- 使用100U虚拟初始资金；
- 模拟 Maker 买单、卖单和部分成交；
- 模拟持仓和收益；
- 按真实市场最终结果模拟结算盈亏；
- 模拟自动赎回和资金回到账户；
- 不调用真实下单、撤单和链上赎回接口。

### 2. 实盘模式

实盘模式与测试模式使用相同的筛选、预算和买卖规则，区别仅在于提交真实订单。实盘策略初始总资金设为100U。

进入实盘模式时需要二次确认。实盘凭证、签名和下单逻辑必须放在后端，不能放在浏览器页面中。

系统不自建地域限制名单，也不主动限制用户所在地区。实盘下单如被Polymarket拒绝，程序应记录平台返回原因，停止新增订单并提示用户，不得持续重复提交。

### 3. 模式切换

- 测试订单、测试持仓和测试余额与实盘数据分开保存；
- 测试订单不能转换为真实订单；
- 切换到实盘时，只对切换后新产生的交易信号提交真实订单；
- 切换回测试模式时，停止新增真实买单并撤销未成交真实买单；
- 已有真实卖单和真实持仓继续由后台管理，直到卖出、结算并完成自动赎回。

## 三、市场筛选

### 1. 市场类别

支持多选：

- 全部市场；
- 政治；
- 体育；
- 加密货币；
- 经济；
- 金融；
- 科技；
- 娱乐；
- 其他 Polymarket 分类。

默认：全部市场。

### 2. 市场总时长

市场总时长：

`预计结束时间－开放交易时间`

采用上限滑块，节点为：

`1、7、14、30、60、90、120、180、360、365天`

其中：

- 总时长不足完整1天的市场固定排除；
- 1表示只显示总时长恰为1天的市场；
- 拉到30表示只显示总时长不超过30天的市场；
- 默认值为30天。

### 3. 市场当前进度

市场当前进度：

`（当前时间－开放交易时间）÷市场总时长×100%`

进度滑块为1%至100%的上限筛选。

例如设置20%，只显示当前进度在0%—20%以内的市场。

默认值：20%。

市场进度超过用户保存的进度上限后：

- 撤销该市场未成交买单；
- 禁止新增买单；
- 已成交持仓和卖单继续保留。

### 4. 事件结果数

第一版只处理结果明确且结果数不超过3个的事件：

- 普通二元事件记为2个结果；
- 互斥型多结果Event最多包含3个明确结果；
- 每个底层Market仍按照YES／NO二元Token处理；
- 暂不处理超过3个结果、未命名占位结果、结果范围仍可能变化的Other，以及结构不明确的多市场Event。

默认：2个或3个结果。

### 5. 交易方向

支持：

- 只交易 YES；
- 只交易 NO；
- YES 或 NO 均可。

默认：YES 或 NO 均可。

### 6. 买入价格范围

买入价格为连续区间：

`1—3美分，即0.01—0.03 USDC`

不是只交易1、2、3三个整数价格，也可以在1.1、1.5、1.6、2.3、2.8美分等合法价格成交。

## 四、固定金额买入

### 1. 单 Token 预算

每个 Token 每轮固定投入1U。后续如有需要，可再调整为其他金额。

1U为该 Token 本轮交易允许使用的全部买入成本上限，包含该笔买入的全部实际成本。

计算方式：

`买入份数＝固定金额÷买入价格`

例如每单投入1U：

| 买入价格 | 理论买入份数 |
|---:|---:|
| 1美分 | 100份 |
| 1.5美分 | 约66.67份 |
| 1.6美分 | 62.5份 |
| 2美分 | 50份 |
| 2.5美分 | 40份 |
| 3美分 | 约33.33份 |

实际数量按平台允许的数量精度向下取整。

### 2. 策略总预算

系统必须设置策略总预算，避免同时对过多 Token 下单。

始终满足：

`已成交买入金额＋活动买单最大占用金额≤策略总预算`

默认建议：

- 测试模式初始总资金：100U；
- 实盘模式初始总资金：100U；
- 单 Token 每单固定投入：1U。

用户可以自行调整。

---

## 五、Maker 买单

### 1. 订单方式

所有买单统一使用：

`GTC 限价单＋Post Only`

规则：

- 只做 Maker；
- 不主动吃单；
- 不自动转为 Taker；
- Post Only 被拒绝时，重新计算合法 Maker 价格或等待。

### 2. 自动买价

每个 Token 只挂一张买单，不在1—3美分之间分层挂多张订单。

自动买价：

`候选买价＝当前最优买价＋1个tick`

同时满足：

- 不超过3美分；
- 不达到或超过当前最优卖价；
- 符合该市场当前 tick size。

如果“最优买价＋1个tick”会触及最优卖价，则使用当前最优买价。

### 3. 买单追价

第一版不频繁追价。

仅当当前最优买价与本方挂单价格明显偏离，且持续一段时间后，才允许撤单重挂；新价格仍不得超过3美分。

追价功能可以关闭。

---

## 六、固定卖价

买入成交后，按该批实际成交价格计算固定卖价。

设实际买入价格为 `B`：

`理论卖价＝max（B＋0.01，B×1.5）`

最终卖价按照该市场当前 tick size 向上取整。

典型示例：

| 实际买入价 | 固定卖价 |
|---:|---:|
| 1.0美分 | 2.0美分 |
| 1.2美分 | 2.2美分 |
| 1.5美分 | 2.5美分 |
| 1.6美分 | 2.6美分 |
| 2.0美分 | 3.0美分 |
| 2.2美分 | 3.3美分 |
| 2.5美分 | 3.75美分 |
| 2.8美分 | 4.2美分 |
| 3.0美分 | 4.5美分 |

所有卖单统一使用：

`GTC 限价单＋Post Only`

卖单规则：

- 不使用移动止盈；
- 不主动降低卖价；
- 不设置价格止损；
- 不转为 Taker；
- 卖不掉则持有至结算。

---

## 七、部分成交

### 1. 买单部分成交

买入多少，就立即对已成交数量挂出对应卖单。

例如：

- 买单计划500份；
- 当前成交200份；
- 系统立即对200份挂卖单；
- 剩余300份买单继续等待。

### 2. 不同价格成交

不同成交价格按批次分别计算卖价。

例如：

- 100份在1.5美分成交，挂Sell 2.5；
- 100份在1.6美分成交，挂Sell 2.6。

### 3. 首次卖出成交

任意卖单首次发生成交后：

- 立即撤销该 Token 剩余未成交买单；
- 停止继续增加该 Token 仓位；
- 尚未卖出的持仓继续保留原固定卖单。

同一Token在一次策略运行周期内只建立一次交易闭环。首次卖出后，该Token在本次策略运行周期内永久停止新增买入；只有用户在暂停或停止状态下明确点击“开始新一轮”，且该Token已完整卖出并尚未正式结算，才可以重新参与交易。新一轮不清空其他持仓、卖单、资金或历史盈亏，其他未被周期锁定的合格Token仍可持续自动交易。

### 4. 成交去重

系统必须保存已处理成交ID。

同一成交消息重复到达时，不得重复挂卖单、重复扣减预算或重复增加持仓。

---

## 八、买单撤销条件

满足任一条件即撤销未成交买单：

1. 市场进度超过用户保存的进度上限；
2. 当前最优买价超过3美分；
3. 市场停止接受订单或停止交易；
4. 该 Token 已发生首次卖出成交；
5. 用户暂停程序或切换回测试模式；
6. WebSocket断线，无法确认行情或订单状态。
7. 体育市场已经开始比赛。

部分成交后，仅撤销未成交数量，已成交持仓继续管理。

体育市场开始比赛后，禁止新增或重新挂出买单；已有持仓和卖单继续按照原规则管理。

---

## 九、自动结算监测与自动赎回

卖单未成交时：

- 不降价；
- 不止损；
- 不主动强制退出；
- 市场仍开放时继续保留卖单；
- 市场停止交易后持有至结算。

需要明确：市场最终结果由 Polymarket 的结算机制确定，程序不自行判定胜负。程序负责自动监测市场是否已经正式完成结算，并在结果确认后处理持仓。

### 1. 自动结算监测

市场停止交易后，系统将该持仓转为“等待结算”状态，并定期检查：

- 市场是否已经正式结算；
- 获胜结果对应的 Token；
- 当前钱包中可赎回的获胜 Token 数量；
- 市场是否处于延期、争议或尚未最终确认状态。

处理规则：

- 尚未正式结算：继续等待，不执行赎回；
- 市场延期或争议：继续等待最终结果；
- 所持方向失败：Token 价值归零，记录全部损失并关闭仓位；
- 所持方向获胜：进入自动赎回流程。

### 2. 自动赎回

获胜仓位确认后，系统自动调用 Polymarket 对应的赎回流程，通过 CTF 赎回流程将获胜 Token 兑换回平台结算资产。

程序内部使用“结算资产”作为统一字段；按当前 Polymarket 机制，赎回后返回 pUSD。

自动赎回前必须确认：

- 市场已正式结算；
- 当前钱包确实持有该市场的获胜 Token；
- 赎回数量大于0；
- 相同市场尚未成功赎回；
- 钱包签名和赎回权限可用。

每个市场使用 Condition ID 作为唯一赎回标识，防止重复赎回。

### 3. 赎回结果

赎回成功后：

1. 获胜 Token 被销毁；
2. 对应结算资产返回钱包；
3. 更新可用余额；
4. 释放该仓位占用资金；
5. 计算并记录最终收益；
6. 将该笔交易标记为已完成；
7. 返还资金可以继续用于后续自动交易。

赎回失败时：

- 保留原持仓状态；
- 不重复记账；
- 记录失败原因；
- 稍后自动重试；
- 连续失败时在页面显示“赎回异常”，等待用户检查。

### 4. 一次性准备

实盘首次启用自动赎回前，需要完成钱包及相关合约的必要授权或账户初始化。该准备由用户确认一次，后续符合条件的获胜仓位由程序自动赎回，无需逐笔确认。

测试模式不执行链上操作，但按照相同规则模拟结算、赎回、余额回收和最终收益。

## 十、测试模式成交规则

测试模式不能简单以“价格碰到挂单价”作为成交条件。

第一版采用保守的队列模拟规则：

1. 虚拟订单挂出时，记录同一价格档位前方可见订单数量；
2. 虚拟订单挂出后，累计同一价格档位的真实成交量；
3. 前方可见数量只通过真实成交量抵扣，前方订单撤销暂不计入，避免高估成交概率；
4. 累计真实成交量超过前方可见数量后，超出的部分才计入虚拟订单成交；
5. 超出部分不足以覆盖虚拟订单时，按超出数量记录部分成交；
6. 行情或成交数据不完整、顺序异常或断线期间，不判定新增虚拟成交；
7. 虚拟订单撤销重挂后，重新记录新价格档位的前方可见数量。

例如虚拟买单前方可见数量为1000份，虚拟订单为50份。后续累计真实成交1020份时，虚拟订单成交20份；累计达到1050份时，虚拟订单全部成交。

测试模式不改变真实订单簿，也不会占用真实资金。

测试模式和实盘模式共用相同的市场数据、筛选、定价、预算、持仓和结算规则。两者仅替换执行适配器：测试模式在本地模拟订单与成交，实盘模式向Polymarket提交真实订单并以平台返回的订单和成交结果为准。

## 十一、数据与刷新频率

### 1. 推荐频率

| 操作 | 频率 |
|---|---:|
| 全市场扫描 | 每15秒 |
| 全量市场同步 | 每3分钟 |
| 市场进度计算 | 每1秒，本地计算 |
| 候选市场行情 | WebSocket实时 |
| 个人订单与成交 | User WebSocket实时 |
| 买入成交后挂卖单 | 事件触发，立即执行 |
| 首次卖出后撤买单 | 事件触发，立即执行 |
| 平台订单核对 | 每10秒 |
| 页面活动数据刷新 | 每500毫秒至1秒 |
| 市场停止交易后的结算检查 | 每30秒 |
| 结算确认后的自动赎回 | 立即执行 |
| 赎回失败后的重试 | 每60秒 |

### 2. 必须保存的数据

第一版只保存：

- 当前策略参数；
- 当前运行模式；
- 测试买单、卖单、成交和持仓；
- 实盘买单、卖单、成交和持仓；
- 已占用预算；
- 已处理成交ID；
- 最终结算结果和收益；
- 自动赎回状态、交易哈希和回收金额。

使用 SQLite 即可。

## 十二、断线和重启

### 1. WebSocket断线

- 暂停新增买单；
- 已经挂在平台上的订单仍保留；
- 自动重连；
- 重连成功后同步平台订单和持仓；
- 同步完成后恢复运行。

### 2. 程序重启

程序重启后：

1. 读取本地数据库；
2. 同步平台真实活动订单；
3. 同步真实持仓和近期成交；
4. 补充遗漏的卖单；
5. 核对完成后恢复运行。

已有真实仓位和卖单不能因为程序进入测试模式而停止管理。

## 十四、技术结构

### 前端

可使用：

- HTML；
- CSS；
- JavaScript或TypeScript；
- 也可以使用React或Next.js。

前端只负责参数设置、数据显示和操作控制。

### 后端

建议使用：

`Node.js 24＋TypeScript`

负责：

- 市场扫描；
- WebSocket监听；
- 筛选；
- 预算计算；
- 测试成交；
- 真实下单和撤单；
- 部分成交处理；
- 自动挂卖单；
- 结算状态监测；
- 自动赎回；
- 余额回收和仓位关闭；
- 数据保存；
- 重启恢复。

### 数据库

第一版使用：

`SQLite`

### 开发与部署

- 项目使用同一套跨平台代码；
- Windows网页端用于项目沟通和页面访问；
- Mac用于本地开发和测试；
- Linux服务器用于后续7×24小时运行；
- 使用Docker Compose统一Mac与服务器运行环境；
- 所有时间在数据库中统一保存为UTC；

- 私钥、助记词、API凭证和签名能力不得进入前端代码、项目仓库或日志。

## 十六、完整执行流程

`扫描开放市场`

→ `按类别、总时长、当前进度和结果数筛选`

→ `拆分YES和NO Token`

→ `筛选连续1—3美分的合法Maker买价`

→ `检查单Token预算和策略总预算`

→ `测试模式创建虚拟买单／实盘模式提交真实Post Only买单`

→ `监听部分成交`

→ `按每批实际成交价格计算固定卖价`

→ `立即挂出对应Post Only卖单`

→ `首次卖出后撤销剩余买单`

→ `市场进度超过用户上限后撤销未成交买单`

→ `卖单成交则完成交易`

→ `卖单未成交则持有至结算`

→ `自动监测市场正式结算结果`

→ `失败仓位归零并关闭`

→ `获胜仓位自动赎回`

→ `结算资产回到可用余额`

→ `记录最终收益并彻底关闭交易`

## 十七、第一版不开发的功能

以下功能暂不纳入第一版：

- 移动止盈；
- 价格止损；
- 临近结算降价；
- 强制平仓；
- 复杂市场评分；
- 多级风险状态机；
- 复杂审计体系；
- 高级收益图表；
- 多策略并行；
- 超过3个结果的事件；
- 未命名占位结果和动态Other结果；
- 地域限制名单及主动地域判断；
- 精确订单队列位置预测；
- 短信或邮件提醒。

第一版只实现核心目标：

**固定金额自动买入连续1—3美分的市场 Token，成交后自动挂固定 Maker 卖单；未卖出则持有至结算，获胜后自动赎回，资金返回账户并完成交易闭环。**
