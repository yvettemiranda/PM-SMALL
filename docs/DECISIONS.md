# 已确认规则

以下规则为当前项目基线，后续修改必须记录原因、日期和影响。

## 项目与运行环境

- 本项目为全新独立项目，与其他交易系统无关；
- 开发目标环境为macOS，部署目标环境为Linux服务器；
- 统一使用Node.js 24、TypeScript和UTC时间；
- 同一套策略逻辑同时服务PAPER和LIVE，差异仅位于执行适配器；
- 同一时刻只允许一个实盘实例拥有下单权。

## 市场范围

- 第一版只处理结果明确且结果数为2或3的事件；
- 普通YES/NO市场视为2个结果；
- 排除结果数超过3、含义不清、动态Other或未命名占位结果的事件；
- 体育市场在比赛开始后停止新买和重新挂买，已有持仓及卖单继续处理；
- 程序不维护地域限制名单，也不主动按地域阻断；若Polymarket拒绝实盘订单，记录错误并停止新订单，不重复尝试，不规避平台限制。

## 交易规则

- 买价范围为0.01至0.03；
- 单笔预算为1U；
- 使用Maker挂单，不主动吃单；
- 同一Token在每轮策略运行中只允许一个完整交易周期；
- 出现第一笔卖出成交后，撤销该Token剩余买单，并永久停止该轮新买，直至人工重置；
- 第一版不扩大到3个以上结果的事件。

## PAPER成交规则

- PAPER和LIVE读取相同的公开市场、盘口和成交数据；
- PAPER订单不进入真实队列，因此成交必须模拟；
- 下单时记录可见的前方排队量；
- 只有下单后同价位累计成交量超过前方排队量的部分，才能计入纸面成交；
- 不把前方撤单计为有利成交；
- 断线、数据缺失或顺序不确定时不确认成交。

## 实盘边界

- 当前版本实盘执行器必须保持禁用；
- 纸面闭环和长时间验证完成前不得接入钱包；
- 钱包密钥不得进入代码、数据库、Git、日志、Issue或聊天；
- 实盘订单被平台拒绝后停止新订单并等待人工处理。

## v0.4.0正式结算规则（2026-08-03）

- 原因：完成纸面闭环，同时避免把市场关闭或临时价格变化误当作正式结果。
- 影响：只有市场`closed=true`且正式结算状态为`resolved`或`settled`时才处理；结果价格必须是二元`1/0`或官方`0.5/0.5`向量，其他状态继续等待。
- 纸面模式不调用钱包、签名、赎回或链上接口；获胜Token回收按正式结果模拟，失败Token归零。
- 使用Condition ID作为一次性结算键；重复结果不重复记账，身份冲突或数据不一致时暂停策略并保留审计记录。

## 全市场分页扫描规则（2026-08-04）

- 原因：用户要求扫描 Polymarket 全部市场，不能因为数据源第一页或本地 Token 数量上限漏掉候选。
- 影响：开放事件使用官方分页迭代器遍历全部页面；不再截断候选 Token 数量，订单簿请求仍按平台批量大小分批读取。
- 市场资格仍需同时满足：事件开放且未关闭/归档，底层市场 active、未关闭、允许下单并启用订单簿，且具备 Condition ID；订单簿和价格规则继续由现有 PAPER 策略校验。
- `MAX_MARKET_DURATION_DAYS` 是筛选参数，默认 30 天；它只决定市场总时长上限，不限制扫描页数或市场总量。
