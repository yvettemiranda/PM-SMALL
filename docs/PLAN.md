## v0.5.0 完成标准

- 遍历全部开放事件分页，并通过同一资格函数按具体市场的用户自定 1–365 天总时长区间、开放/可下单/完整订单簿、`BINARY / TERNARY / MULTI` 类型、Polymarket 首页栏目、1–3¢、有效 Best Bid、Bid/Ask 比例、生命周期进度、最小下单量和体育开赛时间精确筛选；标准 Event 统一支持安全整数 `resultCount >= 2`，不使用事件日期窗口或本地数量上限漏掉候选。
- 未锁 Event 只有全部静态合格兄弟 Token 的盘口新鲜完整时才执行 FAK Preview 和确定性仲裁；执行前必须重算。第一次实际 Fill 在同一事务创建 Event 锁、成交、仓位、targets、资金和盘口消费；0 Fill 不锁。
- TEST 以实时 Best Ask/Best Bid 执行 FAK 买卖，支持部分成交、稳定盘口版本与跨重启消费、动态费用、每笔填充目标、Event 级冻结预算、首次卖出后整 Event 禁买、资金释放重试和完整卖出后自动重新仲裁下一轮。
- 正式关闭后自动 TEST 结算和模拟赎回，账本幂等、守恒、可审计、可恢复。
- 手机和电脑使用同一紧凑单列 UI；配置、资金、持仓和扫描市场行为与后端一致。
- 全量自动测试、类型检查、构建、桌面/手机浏览器验收和双轴代码审查通过；数据库升级原子执行并失败关闭到 `PAUSED`。
- GitHub `main` 与 Linux 服务器运行同一提交；部署前有可核验的 SQLite 和配置备份，部署后保持 `TEST + LIVE_DISABLED + PAUSED`并通过短时冒烟。
- 用户制定并批准正式长期验证计划后，完成约定时长、故障场景、资源/接口容量和数据一致性验收。

## 当前执行顺序

1. Schema 15 任意标准多元升级已完成：安全整数结果数、三类配置、Token/Event 索引、无副作用 FAK Preview、完整兄弟盘口门槛、Event 仲裁、原子锁、冻结预算、退出/结算解锁、迁移兼容、验证、API/UI 与诊断均已落地。
2. 本地全量 29 个测试文件、276 项测试、TypeScript 类型检查、生产构建、前端语法与差异检查均通过；462px/320px PAUSED UI 无横向溢出、无控制台错误，未点击启动 TEST。
3. 当前执行 Standards / Spec 最终复审与 GitHub/Linux 同步；部署前必须先确认服务器 PAUSED、停止容器、备份配置与 SQLite、校验哈希和隔离副本完整性，再以 GitHub `main` 同一提交升级到 Schema 15。
4. 部署后仍停止在正式长期 TEST 前；先复核异常启动来源与启动访问边界，再由用户确认长期验证时长、故障场景、资源门槛、成交样本、证据格式、通过标准和停止条件。
5. 计划确认后才执行长期验证。只有正式验收完成且用户重新明确授权后，才可讨论钱包和 LIVE 实现。

## 持续边界

- 任何阶段都不得用空数据、旧盘口或推测结果冒充成交或结算。
- LIVE 在 v0.5.0 正式长期验证完成前始终禁用；实现和测试通过不等于实盘授权。
- 新增交易状态必须具备幂等、重启恢复、资金守恒和审计记录。
- 每次交付同步更新 `HANDOFF.md`、本文件及必要的变更记录，并核对 GitHub 远端 SHA。
