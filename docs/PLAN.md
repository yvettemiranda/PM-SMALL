## v0.5.0 完成标准

- 遍历全部开放 Event 分页，通过同一资格函数按具体市场的 1–365 天总时长、开放/可下单/完整订单簿、`BINARY / TERNARY / MULTI`、官方栏目、`0.1¢–99¢` 自定买价闭区间、有效 Best Bid、Bid/Ask 比例、生命周期进度、最小下单量和体育开赛时间精确筛选；不使用事件日期窗口或本地数量上限。
- 未锁 Event 只有全部静态合格兄弟 Token 的盘口新鲜完整时才执行 FAK Preview 和确定性仲裁；执行前必须重算。第一次实际 Fill 与 Event Lock、成交、仓位、targets、资金和盘口消费同事务提交；0 Fill 不锁。
- TEST 以 Best Ask/Best Bid 执行 FAK 买卖，支持部分成交、稳定盘口版本与跨重启消费、动态费用、每笔 Fill 按 `min(99¢, tick↑ max(买价+A, 买价×B))` 创建冻结目标、Event 级冻结预算、首次卖出后整 Event 禁买和完整卖出后自动开始下一轮。
- 正式关闭后自动 TEST 结算和模拟赎回，账本幂等、守恒、可审计、可恢复。
- 手机和电脑使用同一紧凑单列 UI；配置、五项资金摘要、持仓、默认折叠的真实交易记录和扫描市场与后端一致。交易记录按成交批次聚合多档 Fill，不以毫秒时间戳替代批次身份。
- TEST 重置只在 `PAUSED` 且双重确认后执行，并固定恢复 100U、1U/Event、二元/三元、全栏目、`0.1¢–99¢`、`+1¢ / ×1.5`、50%、20%、1–30 天，不继承旧服务器环境值。
- 全量自动测试、类型检查、构建、桌面/手机浏览器验收和 Standards/Spec 双轴代码审查通过；数据库迁移原子执行并失败关闭到 `PAUSED`。
- GitHub `main` 与 Linux 服务器运行同一提交；部署前有可恢复的 SQLite 和配置备份，部署后保持 `TEST + LIVE_DISABLED` 并通过 Schema、账本、端口、公网和同库重启验证。
- 全新 TEST 必须从清洁活动数据库和独立基线开始；旧账本只在已验证备份与旧活动证据中保留，不污染新资金、持仓、交易记录或累计时长。
- 用户批准长期验证计划后，完成约定时长、故障场景、资源/接口容量、分段决定和最终数据一致性审计。

## 当前发布顺序

1. Schema 16、可配置最低/最高买价和目标参数、紧凑 UI、五项资金摘要及默认折叠交易记录已落地；2026-08-11 被用户作废的策略研究不在当前范围内。
2. 本地全量基线为 32 个测试文件、309 项测试；TypeScript 类型检查、生产构建、前端语法、正式 TEST 包装脚本语法和差异检查通过。
3. 发布前后必须完成 Standards/Spec 双轴复审；审查发现须先用回归锁定再修复，不能把审查意见留到服务器。
4. 推送后核对 GitHub 远端 SHA；服务器先只读盘点和 PAUSED 备份，再 `pull --ff-only`、迁移到 Schema 16、同库重启并核对公网边界。
5. 旧活动数据因会影响新基线而必须先备份、后重置；只有清洁状态和固定默认配置验证通过后，才按本轮用户授权启动一个新的正式 TEST 并取得首个有效样本。

## 持续边界

- 任何阶段都不得用空数据、旧盘口或推测结果冒充成交或结算。
- LIVE 始终禁用；实现、验证、部署和启动 TEST 都不等于实盘授权。
- 新增交易状态必须具备幂等、重启恢复、资金守恒和审计记录。
- 每次交付同步更新 `HANDOFF.md`、本文件及必要变更记录，并核对 GitHub/服务器实际 SHA。
